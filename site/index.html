Figma pages built from your own library, with the score to prove it.

Lockstep is a Claude Code plugin. It reads your design library through Figma, builds pages from its real components and tokens, then scores the result and fixes it until it passes.

Start in three steps

About five minutes. You need Claude Code and a Figma seat that can edit files. Lockstep checks the rest and tells you how to fix anything that's missing.

  1. Connect Figma to Claude Code

    Once, in a terminal. Then restart Claude Code, type /plugin, open Installed, select figma and sign in.

    claude plugin install figma@claude-plugins-official

  2. Install Lockstep

    Once, in a terminal. The repository is private for now, so ask to be added first.

    claude plugin marketplace add cj-ax/lockstep
claude plugin install lockstep@lockstep

  3. Point it at your library

    In Claude Code, paste your design library's Figma link. Lockstep protects that file so nothing writes to it, then reads its components and tokens.

Four commands

Claude picks the right one from what you ask, or you can name it.

lockstep:init

One-time setup per library. It protects the library file, finds its components and tokens, reads their variants, slots and values from Figma, and saves a summary to lockstep/<library>/ in your project.

How the loop works

Build is the whole loop. It stops when the score and the screenshots both pass, or after three passes.

  1. Read the libraryComponent variants, slots and token values come from Figma's plugin API. Search alone returns no values.
  2. Build in a draftOnly library instances; every fill, stroke, padding, gap and radius bound to a variable; auto layout throughout.
  3. ScoreFive measures and an integrity check, with the offending layers ranked.
  4. LookA screenshot of every frame, because a frame can score 100 and still be broken.
  5. Fix and rescoreRebuild what's structurally wrong; bind raw values that match a token; ask about the rest.

Every write goes to a draft. Three separate checks keep Lockstep out of your library file; the docs below explain them.

What the score measures

Faithfulness is the mean of five measures. Each one matters more than the mean.

MeasureWhat it countsPass
Library instancesContent that is an instance of a library component, rather than text, shapes or painted frames you drewAt the library's ceiling: 100% if it has text components
Bound propertiesFills, strokes, padding, gaps, radius and stroke weight bound to library variables; text using a text style100%
Detached instancesFrames that were once library instances0%
Hard-coded coloursVisible paints with no variable or style, including overrides inside instances0%
Auto layoutFrames you made that use auto layout100%
Integrity issuesContent clipped by its container, text cut off further up, library sample text still showing0

It scored 100. It was still broken.

On Figma's Simple Design System, the first build was all library instances with every value bound, and it scored a perfect 100. The screenshot told a different story: a button nested inside a library button group still read "Button". The next pass fixed that and scored 100 again, with a sentence cut off mid-word.

Both are now integrity checks, and a frame with any integrity issue isn't done, whatever its score. The rescored Slalom build still scores 98 with no issues.

Docs

Where protected keys come from

Keys from all three are combined:

  1. LOCKSTEP_PROTECTED_FILE_KEYS, comma-separated, in the environment
  2. ~/.claude/lockstep.json, for every project
  3. .claude/lockstep.json in the project

Each file holds an object of key and library name, or a plain list of keys. If a file exists but can't be read, every Figma write is blocked until you fix it.

The three guard layers

  1. A PreToolUse hook blocks any Figma write tool whose target names a protected file, including every use_figma call there.
  2. Every write script carries the protected keys and refuses to run if figma.fileKey is one of them.
  3. Every command that writes tells Claude to check the key before each write.

The hook can't see which file Figma desktop has open, so it doesn't cover the third-party figma-console server.

The scripts

All of them run inside Figma through use_figma. render.py fills in each one's placeholders and checks the size limit.

  • inventory.js reads components, variants, slots and token values, in two parts to fit Figma's 48 KB return limit.
  • score.js is read-only and reports the measures, integrity issues and ranked offenders.
  • fix.js binds raw values to tokens with exactly the same value, and lists the rest.
python3 plugin/scripts/render.py score --roots 7:922,7:1302

Scoring an existing design

  1. Ask for lockstep:score with a link to the frames. Nothing is changed.
  2. If raw values could be bound, ask for lockstep:fix. It works on clones placed below your originals.
  3. Hand-drawn parts and broken layout need a rebuild with lockstep:build; binding can't replace a drawn card with a library one.

Frames inside a protected library can't be scored in place. Duplicate them to a draft first.

Limits

  • The numbers come from one run per approach. Read differences of a few points as directional.
  • The Lockstep builds above were made by the same agent that wrote the scorer, so they may be tuned to what it measures. As an independent check, a fresh agent with only the plugin built a page it hadn't seen and scored 99. It still shipped an email field drawn at half width, which the score can't see; the commands now tell it to trust the screenshot.
  • A high score means the page is built from the library, not that it's a good page. Lockstep looks at screenshots for that, and so should you.
  • Finding components depends on Figma's design-system search. Figma has no API to list every component in a library from another file.
  • The build script is written fresh for each page and library; only reading, scoring and fixing are generic. Expect a few passes on a new library.
  • Usage judgement, like which variant means Cancel, comes from your library's component descriptions. When they're thin, Lockstep has to ask.
